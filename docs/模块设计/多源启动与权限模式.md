# 多源启动与权限模式

- **模块定位**：检测 Claude Code 与 Codex CLI，并从受控项目或会话元数据启动新会话、续接或分叉终端。
- **对应代码**：`src-tauri/src/launcher.rs`、`src-tauri/src/lib.rs`、`src/App.tsx`、`src/components/SessionTable.tsx`
- **所属里程碑**：[M1](../roadmap.md#m1)
- **当前状态**：进行中
- **最近更新时间**：2026-08-18

## 职责与边界

前端只提交 provider、项目 ID 或 Session ID、续接方式和最高权限布尔值。Rust 启动器重新扫描本机 catalog，确认该 provider 下存在对应项目或会话和目录，再生成固定命令并拉起新终端。

应用不接管账号登录，也不保存权限模式。最高权限每次启动应用都恢复为关闭，开启时界面持续显示警告。

## 结构与数据流

```text
启动时 / 自动扫描
 ├─ Claude CLI 检测 ─┐
 └─ Codex CLI 检测 ──┴─> 双状态提示

点击新会话
 └─ provider + projectId + highestPermissions
      ├─ 扫描 catalog
      ├─ provider、项目 ID 与目录校验
      ├─ 发现对应 CLI 可执行文件
      └─ Windows Terminal / PowerShell

点击续接 / 分叉
 └─ provider + sessionId + fork + highestPermissions
      ├─ UUID 与 catalog 二次校验
      ├─ 项目目录检查
      ├─ 发现对应 CLI 可执行文件
      └─ Windows Terminal / PowerShell
```

受控命令矩阵：

| Provider    | 新会话   | 续接                   | 分叉                                  | 最高权限附加参数                 |
| ----------- | -------- | ---------------------- | ------------------------------------- | -------------------------------- |
| Claude Code | `claude` | `claude --resume <id>` | `claude --resume <id> --fork-session` | `--dangerously-skip-permissions` |
| Codex       | `codex`  | `codex resume <id>`    | `codex fork <id>`                     | `--yolo`                         |

## 关键决策

1. 后端同时匹配 provider 与 Session ID，避免两个数据源出现相同 ID 时启动错误工具。
2. Claude Code 优先发现 Microsoft Store Claude Desktop 自带的 `claude.exe`，然后再查找 PATH；这能兼容全局 npm 包装脚本失效的机器。
3. Codex 从 PATH 中解析 `.exe`、`.cmd` 或 `.bat`，终端使用解析后的绝对路径。
4. 可执行路径和参数都按 PowerShell 单引号规则转义；Session ID 必须通过 UUID 校验。
5. 最高权限开关不持久化，启用状态使用危险色，并明确显示两种 provider 的实际参数。

## 当前实现

- 顶栏分别显示 Claude 与 Codex CLI 的可用和登录状态。
- 项目树和表格显示来源，工具栏提供 `全部 / Claude / Codex` 筛选。
- Claude 显示消息数，Codex 显示 Token 数；两者都展示模型、分支和来源细节。
- 原会话与分叉续接共享同一套受控启动流程。
- 新会话按当前来源和项目启动，Claude 使用 `claude`，Codex 使用 `codex`；最高权限开关沿用当前启动策略。
- Windows Terminal 缺失时退回独立 PowerShell 窗口。

## 验证方式

Rust 单测覆盖 Claude 与 Codex 的新会话、普通续接、最高权限分叉命令，以及 Claude Desktop 版本号的数字排序。前端单测覆盖 provider 过滤、跨 provider Session ID 隔离和最高权限警告状态。

TypeScript 严格检查、Clippy 零警告、前后端生产构建与 NSIS 打包均已通过。实际终端拉起留给 release 包人工验收，避免自动化检查打开交互式 CLI。
