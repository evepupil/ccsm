# 桌面交互与终端续接

- **模块定位**：提供项目树、会话查找、受控终端续接、工作区恢复和新会话创建的桌面操作界面。
- **对应代码**：`src/App.tsx`、`src/components/ProjectSidebar.tsx`、`src/components/SessionWorkspace.tsx`、`src-tauri/src/catalog.rs`、`src-tauri/src/launcher.rs`、`src-tauri/src/terminal.rs`；M1 扩展见[多源启动与权限模式](多源启动与权限模式.md)
- **所属里程碑**：[M0](../roadmap.md#m0)
- **当前状态**：进行中
- **最近更新时间**：2026-08-26

## 职责与边界

React 界面负责浏览、搜索、筛选、排序、发起续接请求、恢复工作区和创建新会话。Rust 启动器重新从本机索引解析 Session ID 或项目 ID，再创建终端标签。终端探测模块只读检查用户进程树、工作目录和受控 CLI 会话 ID。前端不能提交任意目录、可执行文件或命令文本。

应用不接管 Claude 认证。新终端继承当前 Windows 用户环境，Claude CLI 未安装或未登录时在界面预先提示，实际登录和 Gateway 配置仍由 Claude CLI 处理。

## 结构与数据流

```text
启动 / 自动扫描（每 10 秒）
    │
    ├─ scan_session_catalog ──> 项目树 + 会话表格 + 已打开会话快照
    └─ get_cli_statuses ──────> 双 CLI 状态提示

点击“续接”或“分叉续接”
    │
    └─ resume_session(provider, sessionId, fork, highestPermissions)
           │
           ├─ UUID 校验
           ├─ 重新扫描并解析真实项目目录
           ├─ 探测当前项目及子目录是否已有 Windows Terminal
           └─ Windows Terminal 目标窗口 / PowerShell
                  └─ 固定的 Claude / Codex 续接命令

点击“恢复工作区”
    │
    └─ restore_workspace(projectId, highestPermissions)
           │
           ├─ 校验普通项目和真实目录
           ├─ 从进程树解析项目根目录及子目录中的已打开会话
           └─ Windows Terminal `-w 0`
                 └─ 每条会话创建一个标签并保持项目目录

点击“新会话”
    │
    └─ start_new_session(provider, projectId, highestPermissions)
           │
           ├─ 普通项目：重新扫描并校验来源、项目 ID 和目录
           ├─ 临时会话：创建 Documents/CCSM/日期/new-chat(-N)
           └─ Windows Terminal / PowerShell
                 └─ 固定的 Claude / Codex 新会话命令

左侧“聊天 / 临时会话”
    ├─ 点击行：选择虚拟项目，右侧仍显示现有会话列表
    └─ 点击加号：直接创建独立目录并启动当前来源 CLI
```

## 关键决策

1. 主界面采用固定项目树和可滚动表格，面向大量会话的重复查找，不使用装饰性卡片布局。
2. 搜索跨项目匹配标题、项目路径、分支、模型和 Session ID；点击项目后回到该项目的完整会话列表。
3. “续接”保持原 Session ID，“分叉续接”通过独立图标按钮提供，避免无意制造重复会话。
4. “继续”先查找当前项目根目录及子目录中的 Windows Terminal；找到后通过 `-w 0` 在已有窗口新增标签，查找不到时沿用普通终端启动流程。
5. “恢复工作区”只对当前选中的普通项目生效，按项目根目录及所有子目录筛选已打开会话，并将 Claude 与 Codex 标签集中到一个 Windows Terminal 窗口。
6. 终端扫描只读取进程元数据，不保存命令行、环境变量或终端输出；无法可靠解析 Session ID 的进程计入跳过数。
7. 选中的项目只保存在 WebView 本地存储，不写入 Claude 数据。

## 当前实现

- 可展开项目树及最近六条会话预览。
- 跨项目搜索、按活动时间或标题排序、归档筛选。
- 会话来源、标题、时间、Session ID、消息数或 Token 数、文件大小、分支、模型/版本展示。
- Session ID 复制、原会话续接、分叉续接、项目目录丢失禁用态。
- 通过 10 秒目录扫描同步已打开终端会话；当前项目中的“继续”会优先把标签放入已有 Windows Terminal 窗口。
- 当前项目的“恢复工作区”会解析项目根目录及子目录中的已打开会话，在同一个 Windows Terminal 窗口按会话创建标签；无法识别的会话会反馈跳过数量。
- 在当前选中项目中创建 Claude 或 Codex 新会话，搜索状态下按钮禁用并沿用当前来源和最高权限开关。
- 左侧提供独立的“聊天 / 临时会话”入口；临时目录按日期和 `new-chat(-N)` 命名，持久保留并聚合展示。
- 临时会话仍使用普通会话列表的续接、分叉、归档、复制 ID 和来源标识；列表中显示真实工作目录，悬浮可查看完整路径。
- 自动扫描、空结果、错误、启动中和操作提示状态。
- 系统浅色/深色主题与 900 × 620 最小窗口约束。

## 验证方式

前端单测覆盖相对时间、文件大小、搜索规范化、跨项目搜索、归档过滤、provider 过滤、最高权限警告、排序和工作区启动锁；Rust 单测覆盖项目及子目录边界、Session ID 解析、已有终端判断、工作区会话解析、临时项目聚合和编号目录创建。TypeScript 开启严格模式、未使用变量检查、索引访问检查和可选属性精确检查。

本次通过 `pnpm format:check`、`pnpm check`、22 项前端单测、`cargo fmt --check`、24 项 Rust 单测、Clippy、`pnpm build` 和隔离 `CARGO_TARGET_DIR` 的 `pnpm tauri build --no-bundle`；已生成 x64 EXE。真实点击“继续”和“恢复工作区”后确认 CLI 标签行为仍需人工验收。
