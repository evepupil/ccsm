- **模块定位**：CCSM 前端的组件体系、布局结构与明暗主题。
- **对应代码**：`src/App.tsx`、`src/components/`、`src/hooks/`、`src/lib/sessions.ts`、`src/lib/presentation.ts`、`src/lib/theme.ts`、`src/styles.css`、`src/main.tsx`、`vite.config.ts`；重设计原型位于 `docs/prototypes/ccsm-ui-redesign/`
- **所属里程碑**：[M2](../roadmap.md#m2)
- **当前状态**：进行中
- **最近更新时间**：2026-07-28

## 职责与边界

把后端 `SessionCatalog` 渲染成可筛选、可续接的桌面界面，管理来源切换、搜索、排序、归档与最高权限开关，以及续接 / 分叉 / 复制交互和全局明暗主题。本模块不直接读取会话文件，所有数据经 `src/api.ts` 调用 Tauri 命令获得。

## 结构与数据流

```text
scanSessionCatalog (Tauri)
          │
          ▼
useSessionCatalog ── provider / catalog / selectedProjectId
          │                         │
          │                         └──► AppHeader 来源 Tabs
          │                                  │
          ├──► ProjectSidebar (ListBox) ◄────┘
          │         │
          │         └──► 选择项目并清空全局搜索
          │
          └──► useSessionFilters ──► SessionToolbar (Select / Switch)
                         │
                         └──► SessionTable ──► SessionRow
                                                   │
useSessionLauncher ◄───────────────────────────────┤
          ├──► resumeSession（继续 / 分叉）
          └──► clipboard + HeroUI Toast
```

`App.tsx` 只组装页面，不再集中保存业务状态。`useSessionCatalog` 管理扫描、来源与项目选择，`useSessionFilters` 管理搜索、排序、归档和最高权限，`useSessionLauncher` 管理继续、分叉、复制与启动锁。`selectedProjectId` 通过 `localStorage` 记忆；`selectVisibleProjects` 与 `selectVisibleSessions` 作为纯函数分别计算两侧列表。

## 关键决策

1. UI 库选 HeroUI v3（React Aria + Tailwind v4），无 Provider 包裹、compound 组件 API（`Table.Header`、`Tabs.List` 等），契合 React 19。
2. Tailwind v4 经 `@tailwindcss/vite` 接入；`src/styles.css` 只需 `@import "@heroui/styles"`，该包内部已含 `tailwindcss` + base + 默认主题 + utilities，无需自写 `@plugin` 或 `heroui()` 工厂（v3 与 v2 的主要差异）。
3. 品牌色通过覆盖 CSS 变量 `--accent` 实现：`Button variant="primary"` 等强调控件自动跟随，HeroUI 基于 `--accent` 自动 `color-mix` 派生 hover / soft 色，无需逐组件配色。
4. 暗色：`useSystemTheme` hook 监听 `prefers-color-scheme` 给 `<html>` 切 `dark` class；`styles.css` 用 `@custom-variant dark` 让 `dark:` 工具类跟随同一 class，HeroUI 也通过 `.dark` 触发暗色，三者一致。
5. 操作反馈从自渲染 `notice` 浮层改为 HeroUI Toast（`toast.success / toast.danger` 命令式 API，需 `ToastProvider` 包裹）。
6. 原 893 行手写 `styles.css` 全量废弃，布局改用 Tailwind utility；`styles.css` 仅保留 HeroUI 入口、品牌色覆盖、字体 / 尺寸 base 与 dark 变体声明。
7. provider 徽标等少量品牌色用 Tailwind 任意值 + `dark:` 内联，不引入自定义 CSS class，保持全量重写的自洽。
8. 第二轮重设计原型采用“左侧直接铺项目列表、右上角切换 Claude Code / Codex”的信息结构。来源切换同时更新项目列表与会话列表，项目侧栏不重复放来源筛选。
9. 搜索是当前来源下的全局搜索：左侧只保留命中项目，右侧汇总命中会话；从搜索结果点击项目会清空搜索并进入该项目，避免搜索态和项目态同时高亮造成歧义。
10. 所有项目点击使用受控 `ListBox.onSelectionChange`，来源切换使用受控 `Tabs.onSelectionChange`；HeroUI `Switch` 明确组合 `Switch.Content / Switch.Control / Switch.Thumb`，保证完整轨道、滑块和键盘交互。
11. 任一会话启动期间锁住全部继续与分叉按钮，防止用户在桌面终端启动过程中重复提交。

## 当前实现

- **App.tsx**：仅组装 `AppHeader`、`ProjectSidebar`、`SessionWorkspace` 与 `StatusBar`，保留桌面 header / workspace / footer 三段布局。
- **AppHeader.tsx**：HeroUI `SearchField` 全局搜索、`Tabs` 切换 Claude Code / Codex、图标按钮重新扫描。
- **ProjectSidebar.tsx**：HeroUI `ListBox` 直接铺项目；来源切换和搜索都会同步更新列表，项目数量与会话数量即时变化。
- **SessionToolbar.tsx**：HeroUI `Select` 排序，两个完整 `Switch` 控制归档和最高权限，`Chip` 显示结果数。
- **SessionWorkspace.tsx**：组合工具栏、权限 `Alert`、加载 `Spinner`、错误 / 空数据 `EmptyState` 与会话表格。
- **SessionTable.tsx / SessionRow.tsx**：HeroUI `Table` 渲染会话；每行独立负责信息密度、来源 / 归档 `Chip`、继续、分叉、复制及启动状态。
- **hooks/**：`useSessionCatalog`、`useSessionFilters`、`useSessionLauncher` 分别承接数据源、筛选状态和外部操作，避免组件和 Tauri 调用堆在 `App.tsx`。
- **main.tsx / lib/theme.ts**：`ToastProvider` 与 `App` 同级挂载；`useSystemTheme` 应用系统明暗主题。
- **HTML 重设计原型**：`docs/prototypes/ccsm-ui-redesign/index.html` 可直接打开，样式按令牌、布局、组件拆分，模拟数据与交互脚本独立存放。生产前端已按该原型完成改造并接回真实 Tauri 命令。

## 待扩展项

- JS bundle 592.29KB（gzip 182.14KB），仍有单 chunk 超 500KB 警告，后续可改按需引入 `@heroui/<组件>` 子包做 tree-shaking 优化。
- 最高权限开关已使用 danger 选中色和权限警告；受桌面自动化安全限制，本轮未替用户实际开启该设置，仍需人工确认一次开关状态与警告展示。
- HeroUI 主题目前只覆盖 `--accent`；如需更贴近原设计令牌（warning / danger 色阶），可进一步覆盖对应 CSS 变量。
- Tauri 当前限制最小窗宽为 900px，900px 至 1000px 使用紧凑双栏布局；若以后支持更窄窗口，应改成可折叠侧栏。
